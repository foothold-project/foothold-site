4. 학습 실행: SSH (설정 예정)

4.1 SSH가 정확히 무엇인가

"남의 컴퓨터에 있는 터미널 창을, 내 화면에 띄우는 것"입니다.

내 노트북에서 명령을 치면 워크스테이션이 그 명령을 실행하고, 결과 글자만 내 화면에 돌아옵니다. 계산도 GPU도 전부 워크스테이션 것입니다. 내 노트북은 키보드와 모니터 역할만 합니다.

  • 원격 데스크톱(화면 전체를 그림으로 전송)과 다릅니다. 글자만 오갑니다.
  • 그래서 가볍습니다. GTX 1650 Ti 노트북으로도 아무 문제 없습니다.
  • 학습은 워크스테이션에서 도니, 내 노트북을 닫아도 학습은 계속됩니다(tmux/screen을 쓰면).

4.2 어떤 원리로 연결되나. 네 단계

단계무슨 일왜 필요한가
① 연결노트북이 워크스테이션의 22번 포트로 TCP 접속약속된 문 번호
② 키 교환양쪽이 각자 난수를 만들어 섞어 같은 비밀 열쇠를 만듦 (Diffie–Hellman)⚠️ 이 과정에서 열쇠 자체는 선을 타고 흐르지 않습니다. 중간에서 엿들어도 열쇠를 못 만듭니다
③ 서버 신원 확인서버가 자기 지문(host key)을 보여줌. 처음이면 "이 지문 맞냐" 물음엉뚱한 컴퓨터에 비밀번호를 넘기지 않기 위해
④ 내 신원 증명비밀번호 또는 공개키★ 공개키를 씁니다. 아래 참조

공개키 인증이 왜 더 나은가

열쇠를 두 개 한 쌍으로 만듭니다. id_ed25519(개인키, 내 노트북에만) / id_ed25519.pub(공개키, 서버에 올림).

  • 서버가 "이 난수를 네 개인키로 서명해 봐" 하고, 노트북이 서명해 보냅니다.
  • 서버는 공개키로 검증만 합니다. 개인키는 절대 노트북 밖으로 안 나갑니다.
  • 그래서 서버가 털려도 내 비밀번호는 새지 않습니다. 비밀번호가 아예 없으니까요.
Bash / 우분투
# 노트북에서 한 번만: 키 쌍 만들기
ssh-keygen -t ed25519 -C "jay-laptop"
# 만들어진 공개키를 워크스테이션에 등록하면 끝

4.3 그런데 문제: 학원 밖에서는 안 됩니다

SSH는 상대 컴퓨터에 닿을 수 있어야 씁니다. 워크스테이션 주소는 사설 주소라 같은 학원 망 안에서만 닿습니다. 집에서 붙으려면 공유기에 포트를 열고(포트 포워딩) 공인 IP를 알아야 하는데, 그건 인터넷 전체에 22번 문을 열어두는 것이라 위험합니다.

4.4 그래서 Tailscale: 우리가 잡은 방향

Tailscale은 내 기기들만 들어올 수 있는 사설 네트워크를 만들어 줍니다. 설치하고 로그인하면 각 기기가 100.x.x.x 주소를 하나 받고, 어디에 있든 그 주소로 서로 직접 닿습니다. 공유기 설정도, 공인 IP도, 포트 개방도 필요 없습니다.

항목내용
기반WireGuard (현대 VPN 표준. 빠르고 코드가 작음)
연결 방식가능하면 기기끼리 직접(P2P). 안 되면 중계 서버 경유
우리 요금무료. Personal 플랜 = 사용자 6명 · 기기 무제한 · 태그 리소스 50개
우리 규모워크스테이션 1 + 노트북 5 = 6기기 · 5명 → 무료 범위 안

중요. Tailscale이 SSH를 대체하는 게 아닙니다. Tailscale은 길을 놓고, 그 길 위로 평소 쓰던 SSH가 그대로 다닙니다. (Tailscale SSH라는 별도 기능도 있지만: 전 플랜 사용 가능, Personal은 호스트 5개까지 sshd_config나 authorized_keys를 건드리지 않으므로 나중에 켜도 되고 안 켜도 됩니다.)

구축 순서 (예정)

PowerShell
# ① 워크스테이션: OpenSSH 서버 켜기 (Windows 기본 기능)
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

# ② 워크스테이션 · 노트북 양쪽에 Tailscale 설치
winget install tailscale.tailscale

# ③ 노트북에서 접속: 학원 안이든 밖이든 같은 명령
ssh <계정>@<워크스테이션-tailscale-주소>

⚠️ 아직 설치돼 있지 않습니다. 위는 확정된 방향이고, 실제 구축은 아직입니다. 그전까지는 워크스테이션 앞에서 직접, 또는 화면 공유로만 가능합니다.

정할 것. 팀원 계정을 각자 만들지 공용 하나를 쓸지 · 비밀번호 인증을 끌지 · 학원 네트워크 정책상 Tailscale 사용이 가능한지 확인.

  • 클라이언트 앱으로 실제 접속되는지. 아직 안 해봤습니다
  • 동시 접속 인원. 구조상 프로세스 1개 = GUI 1개 = 화면 1개이므로, 여러 명이 붙어도 같은 화면을 공유할 가능성이 높습니다. 각자 다른 걸 보거나 각자 학습을 돌리는 용도가 아닙니다
  • GTX 1650 Ti 노트북에서 클라이언트가 도는지 (디코딩만 하므로 될 가능성은 높음)
  • 8011·49100 방화벽 규칙 미설정 (열려면 관리자 권한 필요)

"5명이 각자 학습을 돌린다"의 답은 스트리밍이 아니라 SSH입니다.

6. 🔴 반드시 지킬 것. 프로세스 정리

🔴 창을 닫아도 프로세스는 죽지 않습니다

아래는 실측 기록입니다. 규칙이 아니라 실제로 일어난 일입니다.

실측 기록 (2026-08-05): GUI 창을 닫은 뒤에도

출력
PID 66132  살아있음 | CPU 86초 → 7,452초 | RAM 8.52GB | GPU 9GB 점유

창만 사라지고 프로세스는 계속 돌면서 GPU를 먹고 있었습니다.

5명이 각자 좀비를 남기면 GPU 32GB가 금방 차서 아무도 학습을 못 돌립니다.

작업 후 반드시

PowerShell
# 1) 누가 GPU를 쓰고 있나
nvidia-smi

# 2) 내 Isaac Sim 프로세스 확인 (RAM 1GB 이상인 python)
Get-Process python | Where-Object { $_.WorkingSet64 -gt 1GB } |
  Select-Object Id, @{n='RAM_GB';e={[math]::Round($_.WorkingSet64/1GB,2)}}

# 3) 정리
Stop-Process -Id <PID> -Force

# 4) 회수 확인
nvidia-smi

.bat으로 실행했다면 검은 창에서 Ctrl+C로 끄세요. X로 닫으면 좀비가 됩니다.
