분류: 실험 작성: 오흥재 · 2026-08-22 12:02 근거: 실측 요지: 벤치마크를 남이 그대로 다시 돌릴 수 있게 하는 절차. 상태: 확정

작성 2026-08-22 (WS) · 목적: 팀장이 Runpod에서 8/20 일반화 벤치마크를 직접 재현·검증하기 위한 표준 절차. 이 문서를 만들며 원자료를 재검사한 결과, 벤치마크의 통계적 성격에 대한 중요한 발견이 나왔다 (§3). 벤치마크 보고서도 함께 정정했다.

1. 동일 셋업 대조 체크리스트

"같은 실험"이라 말하려면 아래가 전부 일치해야 한다. WS 기준값은 이 워크스테이션에서 실측했다.

#항목WS 기준값 (실측)확인 방법
1체크포인트 해시model_1499.pt SHA256 512d543a… (주의: 1,500 iter의 실체는 model_1499.pt, model_1500은 존재하지 않음) · TorchScript policy.pt 7b47cbe4…팟에서 sha256sum 후 대조. 어느 파일을 로드했는지도 확인
2평가 스크립트WS의 eval_go2.py와 벤치마크 스크립트는 다른 코드다 (판정 5축 vs 1축, 6초·3m vs 20초·10m, env 10 vs 50) → 벤치마크 스크립트 원본이 재현의 전제실행자에게 원본 + 커맨드라인 요청
3Isaac Lab 버전2.3.2, 코어 무수정 (run 폴더 git/IsaacLab.diff 보존)팟에서 VERSION·git diff 확인
4env cfg학습 cfg는 run 폴더 params/env.yaml에 전량 덤프 (seed 42 · 4096 envs · episode 20s)벤치마크의 오버라이드 목록을 스크립트에서 추출
5지형 파라미터10종은 학습 지형 밖 (참고: 지형 가이드 문서)sub-terrain 파라미터·타일·terrain seed 추출
6명령CSV 역산: vx ≈ 0.5 m/s 고정 추정 (3m ÷ 6s, velocity_mae 동일) · WS 8월 초 평가는 vx 1.0 m/s스크립트의 cmd ranges 확인
7판정 임계값progress·tracking·direction 임계는 CSV로 구간 추정만 가능정확한 숫자는 스크립트에서만
8관측235차원 · 노이즈 설정실행 로그의 관측 차원 확인 (알려진 답 테스트)

따라서 이 정정이 중요하다: 8월 초 평가(86.7%, 1.0 m/s·20초·10m)와 이번 벤치마크(0.5 m/s 추정·6초·3m)는 같은 정책의 서로 다른 시험이다. "같은 체크포인트"는 확인됐지만 평가 조건이 달라 수치의 직접 비교는 성립하지 않는다.

2. Runpod 재현 런북 (팀장용)

  • 0단계 (로컬, 과금 0): 체크포인트+params zip·해시 기록 → 벤치마크 스크립트 원본 확보 전에는 팟을 켜지 않는다 (준비는 시계 밖에서, 과금은 시계 안에서).
  • 1단계 팟 생성 (~5분): RTX 4090 · 같은 템플릿(IsaacLab-2.3.2-Go2) · 같은 데이터센터 · 네트워크 볼륨 20~50GB /workspace · 포트 6006(TensorBoard)+8888 노출.
  • 2단계 배치 (~10분): 업로드 → sha256sum 대조 (불일치면 즉시 중단) → pip freeze·VERSION·git diff 스냅샷 저장.
  • 3단계 알려진 답 테스트 (~15분): 통과가 확실한 discrete_obstacles 1종 × 2에피소드만 먼저 → CSV 생성 + overall_success=True + 전진 ≈ 2.85 m 확인. 어긋나면 50회를 돌릴 이유가 없다.
  • 4단계 본 실행 (~1시간): 원 커맨드라인 그대로 headless 실행, 출력은 tee로 보존 → 완료 후 CSV 501행·10지형·빈 값 없음 검사 (조용한 실패 감지).
  • 5단계 TensorBoard: tensorboard --logdir … --host 0.0.0.0 --port 6006 → 콘솔 포트 프록시로 접속.
  • 6단계 대조: 1차 기준 = 지형 10종의 통과/실패 판정 일치. 수치는 ±10% 근사면 합격. 추가로 raw 50행이 이번에도 전부 동일한지 확인 (§3의 결정론 확증 실험을 겸한다).
  • 7단계 철수: 결과를 볼륨에 보존 → NAS로 하향 동기화 → 팟 Terminate. 예상 비용: 총 2~3시간 × $0.74 ≈ $2 내외.

3. 발견: 이 벤치마크는 결정론적 단일 궤적이다

원자료(generalization_raw.csv)를 재검사한 결과, 10개 지형 모두에서 50개 에피소드 행이 (번호 제외) 소수 4자리까지 완전히 동일하다 (지형당 고유 행 = 1). 즉 "지형당 50 에피소드"는 독립 표본 50개가 아니라 결정론적 궤적 1개의 50회 재생이며, 유효 표본은 지형당 n=1이다.

  • 고정 명령 + 결정론적 리셋 + 결정론적 정책(TorchScript)이면 시드는 어디에도 꽂히지 않는다: "시드 비고정 재검에서도 5/10"이라는 후속 실행은 같은 계산의 재실행일 가능성이 높다 가설. 판별법: 재검 raw CSV의 행이 1차와 다른지 확인 (같으면 확정).
  • 올바른 기술: "고정 명령·고정 초기 조건의 결정론적 평가에서 지형 10종 중 5종 통과 판정. 성공률의 구간 추정은 성립하지 않으며, 이 결과는 해당 고정 조건에서의 판정이다."
  • 이것이 벤치마크의 가치를 깎지 않는다: 경계의 존재(어느 지형이 되고 안 되는가)는 명확히 보여줬다. 다만 "성공률 0%/100%"라는 언어가 과장일 뿐이다.

후기 (8/22): v2 재검 파일이 도착해 §3의 판별을 수행했다. 결과: 지형당 고유 행 50/50 = 변동이 실제로 주입됐고 결정론이 해소됐다. 판정은 5/10으로 유지되어 벤치마크의 결론이 통계적으로 견고해졌다. 상세는 벤치마크 보고서 §2-1 참조.

4. 다음 실험 설계 (50회가 의미를 가지려면)

에피소드마다 변동을 실제로 주입한다: ① 초기 자세·yaw 랜덤화 ② 명령을 구간 샘플 (예: vx 0.3~0.7 m/s) ③ terrain seed 변경 ④ 실행 후 raw 행들이 서로 다른지 검사(알려진 답 테스트). 그 뒤에야 지형당 50회에 이항 신뢰구간을 붙일 수 있고, "험지 세트 확정"(결정 안건 1)의 근거 데이터가 통계적 진술이 된다.

5. 실행자에게 요청 (우선순위)

  1. 벤치마크 평가 스크립트 원본 + 커맨드라인 (이것 없이는 재현 정의 불가)
  2. 비고정 시드 재검의 raw CSV (행 단위 비교용)
  3. 로드한 체크포인트 파일 또는 SHA256
  4. 지형 10종 생성 파라미터·terrain seed
  5. 명령 설정 (vx 0.5 고정 추정의 확인) · 판정 임계값 숫자 · 6초·3m 기준의 출처
