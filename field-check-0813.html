분류: 현장 작성: 오흥재 · 2026-08-11 14:15 근거: 현장 준비 요지: 8/13 조선대 방문 때 들고 가는 확인 목록. 답을 채우면 미결정 안건이 닫힌다. 상태: 확정

이 문서는 들고 가는 종이다. 현장에서 답을 채워 오면 프로젝트의 미결정 안건 4개가 한꺼번에 닫힌다. 각 항목에 "이게 왜 중요한가 = 어떤 결정을 가르는가"를 붙였다. 시간이 없으면 🔴 부터 한다.

근거: go2-hardware.md (내부 볼트) §6 «미확인(정직한 공백)» · architecture-decision.md · FLOW.md 같은 날 운영진 조율에서 확정한 것은 8/13 운영 미팅이다. 이 문서는 현장 확인 목록이다.

0. 왜 이 방문이 결정적인가

지금 프로젝트에서 답을 모르는 채 설계를 미루고 있는 것이 4개다.

안건지금 상태이 방문에서 닫히는가
D1 RL 범위 (시뮬만 / 실기 RL 도전)미결정✅ 실기 접근 조건을 알면 닫힌다
D2 증류 채택 여부미결정✅ Orin 등급 + 관측 가용성으로 닫힌다
D3 험지 1종 선정미결정✅ 로봇을 밖으로 낼 수 있나로 갈린다
D5 대여 옵션 A/B미결정✅ 사용 조건을 알면 닫힌다

### ★ 그리고 이 방문의 단 하나의 가장 중요한 질문은 이것이다: # "이 로봇을 학교 밖으로 가지고 나갈 수 있습니까?" 나갈 수 있으면 → 실제 험지(채석장·공사장)에서 촬영·실측·3DGS 스캔이 가능하다. 못 나가면 → 학교 안에 험지를 만들어야 하고, 무대 설계가 통째로 바뀐다.

1. 🔴 반드시 답을 받아 와야 하는 것

1-1. 대여 조건

#물어볼 것왜
①로봇을 교외로 반출할 수 있나? 가능하다면 절차·보험·인솔자 조건은?D3 전체가 여기서 갈린다
②한 번 빌리면 며칠/몇 시간 쓸 수 있나? 연속 대여가 되나?실험 루프를 몇 바퀴 돌 수 있는지 = 일정의 근간
③사용 가능한 요일·시간대. 야간·주말은?학습은 밤에 돌리고 실기는 낮에 → 주 몇 회가 현실적인가
④파손 시 책임 범위. 보험이 있나, 자기부담은?험지 실험을 어디까지 과감하게 할지 결정
⑤옵션 A(교내 한정) → 옵션 B(상시 보유) 전환 조건과 시점D5
⑥사전 예약은 며칠 전에 해야 하나실험 계획을 그만큼 앞서 세워야 함

1-2. 🔴 컴퓨팅 보드: D2(증류)를 가르는 항목

#확인할 것어떻게
⑦Orin NX 인가 Orin Nano 인가. 메모리 몇 GB인가로봇에 SSH 붙어서 cat /etc/nv_tegra_release, jetson_release, free -h
⑧JetPack / L4T 버전cat /etc/nv_tegra_release
⑨Python · ROS2 배포판이 이미 깔려 있나python3 -V, ls /opt/ros/
⑩여유 저장공간df -h

왜: 우리 정책은 파라미터 17만 개(6.9MB)다. Orin NX 급이면 경량화 증류는 불필요하고 관측 증류만 하면 된다. Nano 4GB 급이면 이야기가 달라진다.

1-3. 🔴 저수준 제어가 열려 있는가: 프로젝트 성립 여부

#확인할 것왜
⑪EDU 모델이 맞나 확정: EDU · RJ45 있음 (ROBOT-SPEC)구조적 관문 통과
⑫RJ45 포트 실물 확인 확정: 있음유선 연결 가능
⑬스포츠 모드(MCF)를 끌 수 있나. 저수준(SDK2) 전환이 실제로 되나순정 컨트롤러와 우리 정책은 동시에 못 켠다. 호출은 MotionSwitcherClient.ReleaseMode() 확인됨, 이 개체에서 실제로 되는지가 확인 대상
⑭unitree_ros2 또는 unitree_sdk2 예제가 이미 설치돼 있나있으면 며칠을 번다

2. 🟠 현장에서 5분이면 되는 실측

2-1. 라이다 세대: L1 인가 L2 인가

★ 갱신(8/14): 이 개체는 기본 라이다 외에 등에 별도 Unitree 라이다 모듈이 있다(팀장 확인). 모델명 확인이 더 중요해졌다. 그 모듈이 MCF 와 무관하게 점군을 내면 높이맵을 직접 만들 수 있다 (ROBOT-SPEC §3-2).

왜: 조사 결과 웹페이지 표기 전환만 2026-01~02로 확정됐고 실제 생산 전환일은 미확인이다. L1/L2에 따라 height_scan 대체 가능성이 달라진다.

어떻게: 라이다 모듈 각인·라벨 사진 촬영. 판매처/관리자에게 세대 문의.

2-2. height_scan 이 정말 저수준과 양립 불가한가: ★ 우리 조사의 핵심 가설 검증

조사 결론: rt/utlidar/height_map_array 는 존재하지만 MCF 오도메트리에 의존해서 저수준 제어로 전환하면 끊긴다. 이게 사실이면 증류가 필수로 확정된다.

5분 테스트 (SSH + ROS2 환경이 있다면):

Bash / 우분투
# ① 스포츠 모드 켜진 상태에서 하이트맵이 나오는가
ros2 topic hz /utlidar/height_map_array

# ② 저수준 제어로 전환한 뒤 같은 명령
#    → 여기서 0 Hz 가 되면 우리 가설이 실증된다
ros2 topic hz /utlidar/height_map_array

이 하나가 프로젝트에서 가장 값진 실측이다. 되면 "증류 불필요"라는 대안이 열리고, 안 되면 teacher-student 증류가 유일한 길임이 확정된다.

2-3. 관측 항목 실제 확인

Unitree 공식 실물 배포 코드가 쓰는 관측이 실제로 나오는지 본다.

Bash / 우분투
ros2 topic list | grep -i "low\|sport\|imu\|utlidar"
ros2 topic echo /lowstate --once      # imu_state · motor_state · foot_force
볼 것기대
imu_state.gyroscope · .quaternion🟢 그대로 쓸 수 있어야 함
motor_state[i].q · .dq · .tau_est🟢 관절 각도·속도·토크
foot_force[4]🟠 EDU 전용 + raw 정수 + Unitree 본인이 드리프트 인정
sportmodestate.velocity🔴 MCF 켜져야 나옴 → 저수준과 양립 불가

2-4. 발바닥: 5분에 결판나는 것

조사 §6-①: Go2 족단 센서의 물리 원리가 미확인이다. Go1은 공기압식으로 확정됐으나 Go2 증거가 없다.

어떻게: 발패드를 살펴 에어니들(공기 구멍) 유무를 육안 확인 + 사진. (분해는 하지 말 것. 대여 장비다.)

부록: 현장에서 바로 쓸 명령 모음

Bash / 우분투
# -- 보드 사양 --
cat /etc/nv_tegra_release          # JetPack / L4T 버전
free -h                            # 메모리
df -h                              # 저장공간
nvidia-smi 2>/dev/null || tegrastats --interval 1000   # GPU

# -- ROS2 환경 --
ls /opt/ros/                       # 설치된 배포판
echo $ROS_DISTRO $RMW_IMPLEMENTATION $ROS_DOMAIN_ID

# -- 관측 확인 --
ros2 topic echo /lowstate --once
ros2 topic hz /utlidar/height_map_array

# -- 네트워크 (CycloneDDS 바인딩용) --
