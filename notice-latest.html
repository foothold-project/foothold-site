📌 팀 작업 방식이 바뀌었습니다 · 8월 27일 기준 (읽는 데 4분)

어제 저녁부터 오늘 오전까지 일하는 방식을 다시 짰습니다. 바뀐 것만 모았습니다. git pull origin main 한 번이면 전부 여러분 컴퓨터에 옵니다.

한 장으로 보는 흐름

새로 만든 작업 흐름 한 장이 정본입니다. 이슈를 만드는 것부터 머지까지, 무엇이 자동으로 도는지가 표로 있습니다.

순서무엇을 한다보드
1이슈를 만든다. 본인에게 배정하고 기간을 넣는다Todo (자동)
2폼에서 「작업 영역」 과 「어느 관문까지」 를 고른다라벨·마일스톤 (자동)
3작업 전 브랜치를 판다
4이슈를 In Progress 로 옮긴다손으로. 이것 하나뿐
5작업하고 커밋한다
6PR 을 연다. 본문에 Closes #번호In Progress (자동)
7팀장이 확인한다
8머지되면 이슈가 자동으로 닫힌다Done (자동)

손으로 하는 건 4번 하나입니다. 나머지는 전부 자동입니다.

Closes #29 는 PR 을 열 때가 아니라 머지될 때 이슈를 닫습니다. 그래서 PR 이 먼저입니다. main 에 안 들어간 작업은 아직 끝난 게 아닙니다.

2. 계획 문서를 따로 쓰지 않습니다

이슈를 만드는 것이 곧 계획입니다. 이번 주에 할 것을 이슈로 올리면 그게 Todo 에 박히고 일정 페이지에 반영됩니다.

계획을 문서에도 쓰고 이슈에도 쓰면 한쪽만 고쳐집니다. 실제로 그런 일이 있었습니다.

3. 브랜치 이름

출력
feature/주제-이름      새로 만드는 것

이슈 번호를 붙이지 않습니다. 뒤에 자기 이름을 붙입니다.

4. 어디에 올리나 (바뀌었습니다)

무엇어디에어떻게
문서 (정리 안 된 것 포함)inbox/<내이름>/PR. 팀장이 확인하고 머지합니다. 내용은 손대지 않습니다
코드sim/ nav/ common/브랜치 → PR. inbox 를 거치지 않습니다
정본 문서 docs/직접 고치지 않습니다팀장이 inbox 에서 승격합니다

코드가 inbox 를 안 거치는 이유: 문서는 팀장이 옮겨도 뜻이 안 변하지만 코드는 옮기면 도는지 보장할 수 없습니다.

inbox/ 에 이제 다섯 명 폴더가 다 있습니다 (jay 추가).

5. 문서 머리는 다섯 줄입니다 (네 줄 아님)

출력
> 분류: 리서치
> 작성: 홍길동 · 2026-08-27 09:41
> 근거: 공식 문서
> 요지: 한 줄로 이 문서가 말하는 것
> 상태: 초안
  • 상태 가 새로 들어갔습니다. 초안 · 검토중 · 확정 중 하나입니다
  • 작성 에 시각까지 씁니다. 같은 날 여러 번 고칠 때 순서가 보입니다
  • 분류는 여덟 중 하나: 회의록 리서치 실험 계획 결정 운영 현장 가이드
  • 회의록에는 > 자리: 한 줄이 더 붙습니다: 팀내부 멘토링 운영진 조선대

inbox/ 에는 없어도 됩니다. 없으면 PR 에 봇이 채워진 블록을 코멘트로 달아 줍니다. 복사해서 붙이고 값만 고치면 됩니다.

6. 저장소 이름이 바뀌었습니다

foothold-rl → foothold-go2

RL 이라는 이름이 트랙 B(ROS2·SLAM·Nav2)를 담을 수 없어서입니다. 기존 링크는 GitHub 이 자동으로 넘겨주지만, 새로 적을 때는 새 이름을 씁니다.

폴더도 같이 정리했습니다. lab 과 go2 가 같은 트리를 씁니다.

출력
sim/policy   sim/terrain   sim/eval   sim/twin
nav/src      nav/maps      nav/perception
common/

go2 에는 guide/(재현 절차)와 report/(발표 후 공개본)가 더 있습니다.
