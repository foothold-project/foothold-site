한 장으로 보는 흐름

순서무엇을 한다보드 상태누가
1이슈를 만든다. 본인에게 배정하고 기간을 넣는다Todo (자동)본인
2폼에서 「작업 영역」과 「어느 관문까지」를 고른다라벨·마일스톤 (자동)본인
3작업 전 브랜치를 판다본인
4이슈를 In Progress 로 옮긴다In Progress본인 (손으로)
5작업하고 커밋한다본인
6PR 을 연다. 본문에 Closes #29In Progress (자동)본인
7팀장이 검토한다팀장
8승인·머지되면 이슈가 자동으로 닫힌다Done (자동)자동

손으로 하는 것은 4번 하나뿐이다. 나머지는 자동이다.

자주 틀리는 것

Closes #29 는 PR 을 열 때 이슈를 닫지 않는다. 머지될 때 닫는다. 그래서 PR 을 먼저 열고 이슈는 나중에 닫힌다. 순서를 바꾸지 않는다.

main 에 안 들어간 작업은 아직 끝난 것이 아니다. 이슈를 먼저 닫으면 보드에 Done 으로 뜨는데 코드는 브랜치에만 있다. 보드가 거짓말을 하게 된다.

1. 이슈 만들기

이슈 목록에서 템플릿을 고른다. 빈 이슈로 만들지 않는다.

템플릿언제
작업 등록이런 작업을 하겠다고 미리 올릴 때
실험 기록가설 하나, 변경 하나. 결과를 숫자로 판정할 때 (go2 에만 있다)
리서치답을 모르는 질문이 있을 때 (lab 에만 있다)
막힘·오류안 되는 것이 있을 때

「작업 영역」을 반드시 고른다. 이걸 고르면 라벨과 마일스톤이 자동으로 붙고 보드에서 묶인다. 안 고르면 팀장 텔레그램에 「분류 안 됨」이 간다.

4. 어디에 올리나

무엇어디에어떻게
문서 (정리 안 된 것 포함)inbox/<내이름>/PR. 팀장이 확인하고 머지한다. 내용은 손대지 않는다
코드sim/ nav/ common/브랜치 -> PR. inbox 를 거치지 않는다
정본 문서 docs/직접 고치지 않는다팀장이 inbox 에서 승격한다

코드가 inbox 를 안 거치는 이유: 문서는 팀장이 옮겨도 뜻이 안 변하지만 코드는 옮기면 도는지 보장할 수 없다.

5. 문서를 올릴 때

docs/ 로 승격될 문서는 맨 위에 다섯 줄이 필요하다.

출력
> 분류: 리서치
> 작성: 홍길동 · 2026-08-27 09:41
> 근거: 공식 문서
> 요지: 한 줄로 이 문서가 말하는 것
> 상태: 초안

inbox/ 에는 없어도 된다. 없으면 PR 에 봇이 채워진 블록을 코멘트로 달아 준다. 복사해서 붙이고 화살표 부분만 고치면 된다.

분류는 여덟 중 하나다: 회의록 리서치 실험 계획 결정 운영 현장 가이드

6. 자동으로 도는 것

언제무엇이 일어나나
이슈를 만들면보드에 Todo 로 등록 · 작업 영역 라벨 · 마일스톤 · 팀장 텔레그램
inbox 에 PR 을 올리면디스코드 알림 · 팀장 텔레그램 검수 결과 · 머리 다섯 줄 코멘트
PR 을 이슈에 연결하면보드가 In Progress 로
PR 이 머지되면이슈 자동 닫힘 · 보드 Done · 승격 검토 이슈 생성

7. 검사는 두 곳에서 한다

언제 걸리는지가 다르다. PR 을 올릴 때와 웹을 배포할 때가 별개다.

언제무엇이 검사하나걸리면
PR 을 올릴 때review_inbox.py막지 않는다. 알려만 준다. PR 코멘트와 팀장 텔레그램
웹을 배포할 때빌드 관문 (팀장 쪽 볼트 저장소)배포가 멈춘다. 팀장이 고쳐야 나간다

팀원이 올린 것은 PR 단계에서 막히지 않는다. 다만 정본으로 승격되어 웹에 나갈 때 아래에 걸리면 배포가 멈춘다. 그래서 미리 맞춰 주시면 팀장이 다시 고칠 일이 없다.

검사무엇을 막나
em dash가로로 긴 줄표. · 나 쌍점으로 바꾼다
선 도식선으로 그린 글자 그림. 표로 바꾼다
메타데이터머리 다섯 줄이 없거나 형식이 틀린 문서
링크깨진 내부 링크
민감정보비밀번호 · 토큰 · 개인 연락처 · 예산 금액

8. 절대 하지 않는 것

금지왜
비밀번호 · 토큰 · 개인 연락처를 저장소에 적기공개 웹으로 나간다. 지워도 이력에 남는다
조선대 강의 자료 원본을 저장소에 넣기조선대 저작물이다. 자료실(암호)에만
예산 금액을 공개 문서에 적기대외비다
main 에 직접 push · force push남의 작업이 사라진다
100MB 넘는 파일GitHub 이 거부한다. NAS 나 클라우드에 두고 링크만 남긴다
docs/ 를 직접 고치기남의 작업이 사라진다. inbox 로 올린다

9. 막히면

이슈를 「막힘·오류」로 올린다. 에러 메시지를 그대로 붙여넣으면 된다. 정리하지 않아도 된다. 빨리 알릴수록 되돌리기 쉽다.
