자동화 지도

여러분이 올린 것이 어디로 가고, 무엇이 저절로 일어나고, 어디서 사람이 필요한가.

팀원이 하는 일 자동으로 일어나는 일 팀장이 판단하는 일 아직 자동이 아닌 것
01

제출부터 게시까지

가장 자주 쓰는 길입니다. 여러분이 하는 일은 두 개뿐입니다. 커밋하고, PR을 올리는 것. 나머지는 기계가 합니다.

02

이슈로 일을 나눈다

«무엇을 할지»를 먼저 선언하는 곳입니다. 이슈를 만들면 보드에 자동 등록되고, 디스코드에도 알림이 갑니다. 세 가지 중에 고르면 됩니다.

작업

«이런 작업을 진행합니다» 하고 선언. 무엇을 하나 + 끝났다는 기준. 두 문장이면 충분합니다.

리서치

답을 모르는 질문 하나. 왜 궁금한지 적으면 더 좋지만 필수는 아닙니다.

막힘 · 오류

안 되는 것. 에러 메시지를 그대로 붙여넣으면 됩니다. 정리 안 해도 됩니다.

«리서치» 템플릿이 그동안 고장나 있었습니다. 템플릿이 지정한 라벨이 저장소에 없어서 이슈 생성이 실패했습니다. 한 번 실패하면 다시 안 쓰게 됩니다. 2026-08-25 에 고쳤습니다. 이제 세 가지 다 됩니다.

이슈에 일어나는 일누가언제
보드에 자동 등록자동이슈를 여는 즉시
디스코드 알림자동열릴 때 · 닫힐 때
갈래별 하위 이슈 연결자동본문에 갈래를 적으면
마감 지난 것 이름과 함께 호출자동평일 오전 9시
실적 종료일 기록자동이슈를 닫을 때
주간 리포트자동매주

마감 알림은 지난 것이 없으면 아무 말도 하지 않습니다. 매일 «이상 없음»을 보내면 곧 아무도 안 보기 때문입니다.

03

그 밖에 저절로 도는 것

무엇언제어디로
조선대 강의 자료 감시매일 10시 · 16시새 자료가 올라오면 디스코드 · 팀장 텔레그램
main 직접 push 감시push 될 때디스코드. 규칙을 깬 것을 조용히 넘기지 않는다
공지 발송팀장이 실행디스코드. 원고는 저장소에 남는다
주간 다이제스트일요일 21시이번 주에 무엇을 했는지 자동 정리
사이트 게시docs 에 문서가 들어오면웹페이지 자동 생성 · 배포

강의 자료 감시는 알림까지만 자동입니다. 자료실은 암호를 걸어 올리는데 그 암호가 팀장 PC 에만 있어서, 실제 게시는 팀장이 합니다. 이것은 고장이 아니라 일부러 그렇게 둔 것입니다.

04

아직 자동이 아닌 것

정직하게 적습니다. 자동이라고 믿고 있다가 안 되는 것이 가장 위험합니다.

무엇왜 자동이 아닌가
머지내용 판단이 필요하다. 다만 폰에서 «/머지» 코멘트로 할 수 있게 해두었다
승격 (웹 게시 여부)같은 이유. 이슈에 «/승격» 코멘트
자료실 업로드암호가 팀장 PC 에만 있다. 감지 · 내려받기까지 자동화하고 게시는 팀장이 «/머지» 로 하는 방향으로 진행 중
회의록 작성녹음 전사는 자동, 무엇이 결정이었나는 사람이 정한다
코드 리뷰기계는 형식만 본다. 옳은지는 사람이 본다
05

브랜치와 커밋

이미 정해진 규약입니다. docs/COLLAB.md 5절에 있습니다. 여기서는 요약만 합니다.

저장소규칙
rl코드를 바꿀 때만 브랜치를 판다. feature/작업명-이름 (예: feature/terrain-lim) → PR 로 dev → 검증된 것만 PR 로 main
lab팀원은 브랜치 → PR. main 직접 커밋은 팀장만. inbox 제출도 같다
site · brand파이프라인이 관리한다. 직접 커밋하지 않는다

이슈마다 브랜치를 만들 필요는 없습니다. 브랜치는 이슈가 아니라 «PR 로 합칠 코드 변경» 단위입니다. 조사 · 회의 · 막힘 이슈는 브랜치가 아예 필요 없고, 작은 이슈 여럿을 브랜치 하나로 처리해도 됩니다.

이슈 번호를 브랜치 이름에 넣지 않습니다. 권장이지 의무가 아니고, 우리는 넣지 않기로 했습니다. 이름은 작업명-본인이름 이면 충분합니다.

대신 이것만은 반드시. 추적의 핵심은 브랜치 이름이 아니라 커밋이나 PR 본문의 Closes #번호 입니다. 이 한 줄이 있어야 이슈가 자동으로 닫히고, 보드가 움직이고, 실적 날짜가 기록되고, 디스코드 알림이 나갑니다. 이것을 빠뜨리면 위의 자동화가 통째로 걸리지 않습니다.

머지된 브랜치는 자동으로 지워집니다. 브랜치는 소모품입니다.

06

AI 를 쓸 때

AI 로 코드를 쓰거나 조사하는 것은 권장합니다. 다만 올리기 전에 아래는 지켜 주세요. 우리 문서는 밖에 나가고, 잘못된 숫자 하나가 프로젝트 전체의 신뢰를 깎습니다.

AI 가 썼어도 올리는 사람은 본인

«AI 가 그랬다» 는 근거가 되지 않습니다. 본인이 읽고 이해한 것만 올려 주세요. 이해 못 한 부분이 있으면 PR 에 «이 부분은 잘 모르겠습니다» 라고 적어 주세요. 숨기는 것보다 낫습니다.

지어낸 것을 거른다

AI 는 논문 제목 · 수치 · 함수 이름 · 링크를 그럴듯하게 만들어 냅니다. 링크는 실제로 열어보고, 수치는 어디서 나왔는지 확인하고 올려 주세요.

직접 본 것과 들은 것을 구분

문서에 확인됨 · 추측 · 미측정 을 붙여 주세요. 내가 돌려본 것과 AI 가 말한 것은 다릅니다. 이 표기가 없으면 자동 검토가 «손질 필요» 로 돌려보냅니다.

비공개 자료를 통째로 넣지 않는다

조선대 제공 자료는 저작물입니다. 팀 내부 문서 · 계정 정보 · 개인정보도 마찬가지입니다. AI 에 통째로 붙여넣지 마세요. 필요하면 요약해서 묻거나 공개된 부분만 쓰세요.

코드는 돌려보고 올린다

자동 검토는 형식만 봅니다. 돌아가는지는 보지 않습니다. 「생성했다」 가 아니라 「돌려서 이렇게 나왔다」 를 PR 에 적어 주세요.

AI 사용을 숨길 필요는 없다

커밋이나 PR 에 「AI 로 초안을 만들고 확인했습니다」 라고 적어도 됩니다. 오히려 무엇을 검증했는지 알 수 있어 좋습니다.

07

신경 쓰지 않아도 되는 것

이미 처리되도록 만들어 두었습니다. 여기 적힌 것을 걱정하느라 시간을 쓰지 마세요.

이것어떻게 처리되나
팀장에게 알리기PR 을 여는 순간 디스코드와 텔레그램으로 자동으로 갑니다. 따로 연락하지 않아도 됩니다
보드에 등록하기이슈를 만들면 자동으로 올라갑니다
개인정보가 섞였나기계가 먼저 훑습니다 (전화번호 · 주민번호 · 주소). 다만 최종 책임은 본인입니다
마크다운을 웹페이지로승격되면 페이지 · 목차 · 검색 색인 · PDF 저장까지 자동으로 만들어집니다
파일 이름 규칙팀장이 정돈합니다. 편한 이름으로 올리세요
문체 규칙 (em dash 등)빌드가 막습니다. 어긴 채로는 게시되지 않습니다
다크 모드 · 모바일 대응자동입니다
브랜치 지우기머지되면 자동으로 지워집니다

완벽하게 쓰려다 안 올리는 것이 가장 나쁩니다. 형식은 위 장치들이 받아 줍니다. 여러분이 신경 쓸 것은 내용이 맞는가 하나입니다.

08

AI 에이전트에게 시킬 때 걸리는 것

이 지도만 읽고 AI 에게 일을 시키면 거의 확실하게 걸리는 것들이 있습니다. 기계가 막기 때문에 조용히 넘어가지 않고, 빌드가 멈추거나 자동화가 통째로 안 걸립니다.

AI 가 하기 쉬운 것무슨 일이 나나
긴 줄표(em dash)를 쓴다빌드가 멈춥니다. AI 는 이 문자를 습관적으로 씁니다. 우리 문체 규칙에서 금지라 배포 직전 관문이 잡아냅니다
글자로 그린 도식을 만든다빌드가 멈춥니다. 박스·화살표·트리 가지를 글자로 그린 것은 웹에서 깨집니다. 표나 SVG 로 바꿔야 합니다
git push origin main 을 시도한다막혀 있지는 않지만 디스코드에 알림이 갑니다. 그리고 자동화가 전부 건너뛰어집니다
보드에서 + Add item 으로 항목을 만든다저장소에 없는 가짜 이슈(draft)가 되어 자동화가 하나도 안 붙습니다
커밋에 Closes #번호 를 안 넣는다이슈가 안 닫히고 보드도 안 움직이고 실적 날짜도 안 남습니다
출처와 수치를 그럴듯하게 지어낸다사실 검증 관문이 잡아 배포를 중단합니다. 링크는 실제로 열리는지 확인해야 합니다
확인됨 표기 없이 문서를 쓴다자동 검토가 «손질 필요» 로 돌려보냅니다
site · brand 저장소를 직접 고친다파이프라인이 관리하는 곳입니다. 다음 빌드에 덮어써집니다

AI 에게 먼저 알려주세요

작업을 시키기 전에 아래를 그대로 복사해 넣으면 위의 사고가 대부분 사라집니다.

복사해서 AI 에게 붙여넣기
[FOOTHOLD 프로젝트 규칙 - 반드시 지킬 것]

문체
- 긴 줄표(em dash) 를 절대 쓰지 마라. 대신 마침표 · 쌍점 · 하이픈 · 가운뎃점을 써라.
- 글자로 도식을 그리지 마라(박스 · 화살표 · 트리). 표로 쓰거나 그림이 필요하다고만 적어라.
- 근거가 있는 것은 `확인됨`, 추측은 `추측`, 안 해본 것은 `미측정` 이라고 표기해라.
- 출처 링크는 실제로 존재하는 것만 써라. 확신이 없으면 링크를 넣지 말고 "출처 미확인" 이라고 적어라.

git
- main 에 직접 push 하지 마라. 브랜치를 만들고 PR 을 열어라.
- 브랜치 이름은 feature/작업명-내이름 형식. 이슈 번호는 넣지 않는다.
- 커밋 메시지나 PR 본문에 Closes #번호 를 반드시 넣어라.
- site · brand 저장소는 건드리지 마라.

제출
- 결과물은 inbox/내폴더/ 아래에 둔다.
- 전화번호 · 주소 · 주민번호 같은 개인정보를 절대 쓰지 마라. 공개 사이트에 나간다.
- 조선대 제공 자료는 저작물이다. 통째로 인용하거나 재배포하지 마라.

확인
- 코드는 실제로 돌려보고, "돌려서 이렇게 나왔다" 를 PR 에 적어라.
- 내가 확인하지 못한 부분은 숨기지 말고 PR 에 그대로 적어라.

AI 에 넣으면 안 되는 것. 조선대 제공 자료 원본, 팀 내부 문서, 계정 정보, 팀원 개인정보. 저작물이고 공개 서비스에 올라가는 순간 통제할 수 없습니다. 필요하면 요약해서 묻거나 공개된 부분만 쓰세요.

09

실수로 main 에 push 했다면

일어납니다. 당황해서 더 큰 사고를 내는 것이 진짜 문제이므로 순서를 적어 둡니다.

팀원이 할 것 (세 가지뿐)

순서무엇을
1아무것도 더 하지 마세요. 특히 --force 는 쓰지 마세요. 되돌리려다 남의 작업을 지웁니다
2무엇이 올라갔는지만 확인해 알려주세요. git log origin/main -3 --oneline
3디스코드에 이미 알림이 갔습니다. 추가로 한 줄만 남겨주세요. 「실수로 push 했습니다. 커밋 abc1234」

혼나는 자리가 아닙니다. 빨리 말할수록 되돌리기 쉽습니다. 숨기면 그 위에 다른 작업이 쌓여 되돌리기가 훨씬 어려워집니다.

팀장이 할 것

상황대응
그냥 잘못 올라간 것git revert <커밋> 로 되돌리는 새 커밋을 만든다. 이력이 남아 안전하다
여러 커밋git revert --no-commit A..B 로 묶어서 되돌린다
내용은 괜찮은데 절차만 어긴 것되돌리지 않는다. 그대로 두고 다음부터 PR 로 오라고 말한다. 되돌리는 것이 항상 정답은 아니다
비밀번호 · 토큰 · 키가 섞였다revert 로는 부족하다. 이력에 그대로 남는다. 그 키를 즉시 무효화하고 새로 발급하는 것이 진짜 대응이다

reset --hard 뒤 강제 push 는 하지 않습니다. 남의 로컬과 어긋나 더 큰 혼란을 만들고, 이미 받아간 사람에게는 아무것도 지워지지 않습니다. 되돌릴 때는 revert 입니다.

10

inbox 제출 : 어디까지 맞춰 오면 되나

최소 규칙만 맞으면 됩니다. 잘 만들어 오셨으면 그대로 올라갑니다. 완벽하게 다듬느라 안 올리는 것이 가장 나쁩니다.

최소 규칙왜
본인 폴더에 넣는다 inbox/본인폴더/누가 낸 것인지 경로로 알 수 있게
개인정보를 넣지 않는다공개 사이트로 나갑니다
긴 줄표 · 글자 도식을 쓰지 않는다빌드가 멈춥니다
확인한 것과 추측을 구분한다안 하면 어디까지 믿을지 알 수 없습니다

부족한 것이 있으면 어떻게 되나

여러분의 글을 마음대로 고치지 않습니다. 대신 이렇게 갑니다.

무슨 일이누가
1기계가 읽고 무엇이 부족한지 판정자동
2보완이 필요하면 같은 PR 에 «보완» 커밋을 따로 올린다. 원문 커밋과 섞지 않는다자동
3무엇을 왜 보탰는지 요약해 팀장 텔레그램으로자동
4팀장이 PR 에서 확인 · 승인하거나 피드백팀장
5승인되면 머지 · 웹 게시자동

보완 커밋을 따로 두는 이유는 «어디까지가 내가 쓴 것이고 어디부터 보태진 것인가» 가 남아야 하기 때문입니다. 여러분의 이름으로 나가는 글입니다.

지금은 여기까지가 완전 자동이 아닙니다. 「무엇이 부족한가」를 판정하는 것까지는 기계가 혼자 합니다. 그러나 실제로 문장을 보태고 출처를 찾아 검증하는 2번 단계는 팀장 워크스테이션의 세션이 붙어야 돌아갑니다.

즉 팀장 PC 가 꺼져 있으면 판정과 알림까지만 오고 보완은 멈춥니다. 자동이라고 믿고 기다리면 안 되므로 적어 둡니다. 이것을 기계 쪽으로 옮기는 작업은 별도로 진행 중입니다.

팀장의 피드백은 PR 코멘트로 남습니다. 여러분도 볼 수 있고, 다음에 낼 때 같은 지적을 안 받게 됩니다.

main 에 직접 push 하지 마세요. 솔직히 말하면 기술적으로 막혀 있지는 않습니다. 무료 플랜의 비공개 저장소에서는 브랜치 보호를 걸 수 없습니다. 대신 직접 push 하면 그 자리에서 디스코드에 알림이 갑니다. 막을 수 없으니 보이게 만들어 둔 것입니다.

브랜치를 만들고 PR 을 여는 것이 번거로워 보이지만, 그 한 줄 덕분에 위의 모든 자동화가 걸립니다. main 에 바로 밀면 알림도, 자동 검토도, 승격 큐도 전부 건너뛰어 버립니다.
